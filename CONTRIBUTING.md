# Contributing

Issues and focused pull requests are welcome.

Before proposing a change:

1. Describe the real task or failure mode the change addresses.
2. Keep the Skill's trigger and authority boundaries narrow.
3. Update the relevant product story, examples, or evaluation cases when behavior changes.
4. Run `npm run validate`, `npm test`, and `npm run build`.

Do not include private conversations, credentials, local absolute paths, personal data, or generated examples presented as real evidence. Packaging checks prove structural integrity; behavior claims should be backed by a reproducible task or clearly labeled as a hypothesis.
